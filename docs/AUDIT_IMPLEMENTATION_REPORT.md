### 2. API Endpoints

**GET /audit**
- Повний звіт аудиту за вказаний період
- Query параметр: `?hours=24` (за замовчуванням)
- Обробка невірного вводу (повертає до 24 годин)
- Приклад: `curl "http://127.0.0.1:8790/audit?hours=1"`

**GET /audit/resources**
- Виконання аудиту ресурсів на вимогу
- Повертає поточний стан всіх сховищ
- Приклад: `curl http://127.0.0.1:8790/audit/resources`

### 3. Інтеграції

**ci.py (головний сервер)**
- Автоматичне логування всіх GET/POST запитів
- Вимірювання часу відповіді
- Класифікація клієнтів
- Graceful degradation при відсутності модуля аудиту

**core/cimeika_system.py**
- Інтеграція `scan_resources()` з модулем аудиту
- Зворотна сумісність зі старим форматом
- Fallback при відсутності модуля аудиту

**core/audit_test.py**
- Розширені GEC-4 тести
- Валідація authorized_links з Matrix
- Логування результатів тестів
- Підтримка різних сценаріїв

## Класифікація клієнтів

Система автоматично визначає тип клієнта:
- **CLI_TOOL** - curl, python-requests, wget, httpie
- **AI_AGENT** - GPT, Gemini, Claude, AI
- **WEB_BROWSER** - Mozilla, Chrome, Safari, Firefox
- **UNKNOWN** - невідомі клієнти

## Інтеграція з GEC Framework

### GEC-2: Strict Least Privilege
- Аудит доступу до ресурсів
- Контроль data_scopes з Matrix

### GEC-3: Automated Repair
- Логування результатів автоматичного ремонту
- Ескалація критичних помилок

### GEC-4: Push Protection (Ci Guard)
- Перевірка мережевих з'єднань
- Валідація authorized_links
- Блокування неавторизованих запитів

## Програмний доступ

```python
from core.audit import get_audit_instance

# Отримати інстанс аудиту
audit = get_audit_instance()

# Виконати аудит ресурсів
result = audit.audit_resources()

# Залогувати API запит
audit.audit_api_request("GET", "/api", "127.0.0.1", "curl", 200, 5.2)

# Перевірити мережевий запит
audit.audit_network_request("NODE-TG-BOT", "https://api.telegram.org", True)

# Отримати звіт
summary = audit.get_audit_summary(hours=24)
```
